# Equal Start evaluations for every agent

The course requirement is evaluated at each specialist boundary, using the exact prompts, schemas, and identifier guards imported by the application. The runner measures model task quality separately from deterministic guard tests and the app's fallback behavior. No hosted evaluation service or extra dependency is required.

## Reproduce

From the repository root, with the configured environment:

```powershell
# Baseline only; no external calls or inference charges.
.\.venv\Scripts\python.exe -m evals.runner

# Paired baseline and live agent runs: 8 cases × 4 agents × 3 repeats.
# Empty cases are no-call guards, so the default suite makes 84 model calls.
.\.venv\Scripts\python.exe -m evals.runner --live --repeats 3 --max-cost 1

# Deterministic contract, scorer, app and regression tests.
.\.venv\Scripts\python.exe -m pytest -q
```

The additional $1 evaluation cap is a sub-limit inside the existing cumulative $15 authorization. The same persistent SQLite budget ledger is used; a new evaluation directory does not reset spending. Live service failures stay recorded failures. The command exits nonzero if a live agent misses its release gate, while still saving its report. Baseline quality is expected to be lower and does not fail the command.

Each run creates a unique directory under docs/evals/ with frozen contexts, expected outcomes, label reasons, dataset/prompt fingerprints, dependency versions, individual repetitions, and aggregate metrics. Files include cases.json, metadata.json, journal.jsonl, results.json, results.csv, REPORT.md, and a standalone dashboard.html. The journal flushes after every result and reports update after every repeat, so interrupted work remains inspectable. An interrupted run is incomplete and must not be presented as a completed evaluation; start a new run to repeat it.

## Fixed criteria

| Agent | Quality metrics | Failure examples |
| --- | --- | --- |
| Discovery | Relevant-ID precision, recall, F1, reciprocal rank | Unrelated results, omitted matches, invented or injected IDs |
| Evidence | Ambiguity-flag precision, recall, F1 | Missed unknown deadline/payment timing, unsupported guarantee, false flag on a clear restriction |
| Fit | Preference-pair ordering and complete candidate preservation | Prioritizing upfront reimbursement when the student cannot pay upfront, ignoring housing or the goal |
| Planning | Prerequisite-pair ordering and complete material preservation | Submission before preparation, references attached before requested, invented indices |

Discovery needs precision and recall of at least 0.80 per case. Evidence needs F1 of at least 0.80. Fit and Planning need all explicitly labeled precedence pairs correct. Every output must satisfy its schema and grounding constraints. An agent's live release gate requires 100% contract validity and at least 90% task-case passes. These gates and expected outcomes were fixed before the first live run.

All agents have normal, empty-input, and prompt-injection cases. Additional slices cover community-college goals, missing dates, unclear costs, contradictory summaries, housing, and document/reference/nomination dependencies. Separate deterministic tests verify rejection of malformed, duplicate, missing, and out-of-context references. Those tests show guard behavior, not that a model never attempts an invalid answer.

## Interpretation

The contexts are synthetic, intentionally small, and authored during the AI-assisted coding session. Expected outcomes are not independent human annotations, were not generated by the evaluated Fireworks model, and are never included in model requests. The fixed regression set was not split into training/test sets because no model is trained or fitted; it is also not independent held-out evidence of generalization. Add independently reviewed real-task cases before drawing broader conclusions.

The baseline reproduces simple local behavior on already-screened inputs. It does not replace hard eligibility checks and is not another model. Metrics use deterministic graders; no LLM judges itself. Three repeats help reveal variation but are correlated, so the report does not claim statistical significance. Exact-output stability can fall for tied rankings without harming task correctness.

Discovery precision and recall apply to the already-screened supplied candidate set, not web-wide discovery or the catalog's first-stage retrieval recall. Evidence can assess ambiguity in supplied summaries; it cannot verify external factual truth without the underlying source text. Fit orders candidates rather than deciding eligibility. Planning sequences existing materials rather than assessing full essay quality. These boundaries define what each score means and prevent a schema-only success rate from being called overall agent accuracy.

Prompt revisions after observing failures are development iterations on the same regression set, not fresh held-out validation. Earlier runs remain in docs/evals/. Grader v2 assigns zero diagnostic quality to contract failures; the earlier grader's diagnostic metric means were conditional on scored outputs. Both versions count contract failures as failed task cases, so unconditional case pass rates remain comparable.
